# مَنيع | MANEE

موقع ومعرض أعمال لشركة مَنيع، مع لوحة إدارة وواجهة API لإدارة المشاريع والخدمات ورسائل التواصل. المشروع يستخدم React وTypeScript وVite للواجهة، وExpress للخادم، وSQLite لتخزين البيانات.

## المتطلبات

- Windows 10 أو أحدث.
- Node.js **22.18 أو أحدث**، أو Node.js 24 LTS. هذا الإصدار مناسب لـ Vite 8 وتشغيل الخادم.
- npm (يأتي مع Node.js).

تحقق من الإصدارات في PowerShell:

```powershell
node --version
npm --version
```

## التشغيل المحلي خطوة بخطوة

### 1. افتح مجلد المشروع

افتح مجلد المشروع الذي يحتوي على `package.json` في VS Code، ثم افتح الطرفية من **Terminal → New Terminal**. أو انتقل إليه من PowerShell:

```powershell
cd "C:\path\to\manee-website-main"
```

إذا كانت الملفات داخل مجلدين متداخلين بالاسم نفسه، انتقل إلى المجلد الداخلي الذي يحتوي على `package.json`.

### 2. ثبّت الحزم

```powershell
npm ci
```

يستخدم npm ملف القفل `package-lock.json` لإعادة تثبيت الإصدارات نفسها، بينما يمكن استخدام Bun اعتماداً على `bun.lock`. استخدم `npm install` فقط عند تغيير التبعيات وتحديث ملف القفل.

### 3. (اختياري) جهّز إعدادات الخادم

يعمل الموقع محلياً بالإعدادات الافتراضية، ولا تحتاج إلى ملف إعدادات لتجربة الصفحات العامة. لإنشاء حساب لوحة الإدارة أو إعداد البريد، أنشئ ملفاً اسمه `.env` في مجلد المشروع، وأضف الإعدادات التي تحتاجها فقط:

```dotenv
PORT=3000
APP_URL=http://localhost:3000
ADMIN_USERNAME=
ADMIN_PASSWORD=
```

يمكنك نسخ `.env.example` إلى `.env` محلياً. احفظ `.env` محلياً ولا ترفع كلمات المرور أو مفاتيح الخدمات إلى Git. عند ترك `ADMIN_PASSWORD` فارغاً في التطوير، تظهر تهيئة إنشاء المدير لأول مرة في `/admin`. لا يظهر اسم مستخدم مُعبأ تلقائياً؛ أدخله بنفسك.

إعدادات اختيارية أخرى:

| المتغير | الاستخدام |
| --- | --- |
| `DB_PATH` | مسار قاعدة البيانات. الافتراضي `./data/manee_portfolio.db`. |
| `STORAGE_ROOT_PATH` | مجلد الصور المرفوعة. الافتراضي `./data/uploads`. |
| `JWT_SECRET` | مفتاح جلسات الإدارة. في الإنتاج استخدم قيمة عشوائية لا تقل عن 32 بايت. |
| `CORS_ALLOWED_ORIGINS` | قائمة عناوين مسموح بها، مفصولة بفواصل. |
| `SMTP_HOST`, `SMTP_PORT`, `SMTP_USER`, `SMTP_PASS`, `SMTP_FROM_ADDRESS` | إعدادات إرسال البريد الإلكتروني. |

يمكن إنشاء مفتاح عشوائي لـ `JWT_SECRET` من PowerShell:

```powershell
node -e "console.log(require('node:crypto').randomBytes(32).toString('hex'))"
```

### 4. شغّل الموقع والخادم

```powershell
npm run dev
```

افتح [http://localhost:3000](http://localhost:3000). هذا الأمر يشغّل Express وواجهة Vite معاً؛ لا تحتاج إلى تشغيل خادم الواجهة وواجهة API في طرفيتين منفصلتين.

روابط مفيدة أثناء التطوير:

- الموقع: [http://localhost:3000](http://localhost:3000)
- لوحة الإدارة: [http://localhost:3000/admin](http://localhost:3000/admin)
- توثيق API: [http://localhost:3000/api/docs](http://localhost:3000/api/docs)
- فحص صحة الخادم: [http://localhost:3000/health](http://localhost:3000/health)

عند التشغيل الأول، ينشئ الخادم قاعدة البيانات والبيانات الأساسية تلقائياً. لإيقافه، اضغط `Ctrl+C` في الطرفية.

## إنشاء نسخة إنتاجية وتشغيلها

من PowerShell، ابنِ الملفات أولاً ثم شغّل الخادم بوضع الإنتاج:

```powershell
npm ci
npm run build
$env:NODE_ENV = "production"
npm start
```

`npm start` يحتاج إلى إعدادات إنتاج صالحة قبل التشغيل. إعدادات `NODE_ENV=production` تتطلب:

- `APP_URL` بعنوان موقعك العام ويجب أن يبدأ بـ `https://`.
- `ADMIN_USERNAME` مخصصاً لك، و`ADMIN_PASSWORD` فريداً لا يقل عن 10 أحرف ويحتوي حرفاً كبيراً وصغيراً ورقماً.
- `JWT_SECRET` عشوائياً لا يقل عن 32 بايت. أنشئ قيمة مستقلة عن كلمات المرور ولا تعِد استخدامها.
- `DB_PATH` و`STORAGE_ROOT_PATH` على قرص دائم (Persistent Volume) تدعمه منصة الاستضافة.
- استخدم HTTPS خلف reverse proxy موثوق، واضبط `CORS_ALLOWED_ORIGINS` على النطاقات الدقيقة فقط عند اختلاف نطاق الواجهة عن API. الخادم يثق بعنوان proxy واحد لأجل تحديد IP وحدود الطلبات.
- اترك `SWAGGER_ENABLED=false` في الإنتاج ما لم تكن بحاجة مقصودة إلى نشر توثيق API.
- شغّل نسخة واحدة من الخادم: التخزين الحالي SQLite ومحلي، وحدود الطلبات محفوظة في ذاكرة العملية. التوسع الأفقي يتطلب قاعدة بيانات وتخزيناً ومحدد معدل مشتركاً.

تعيّن بيانات المدير من متغيرات البيئة عند بدء الخادم. التهيئة الذاتية للحساب (`/admin` bootstrap) مخصصة للتطوير؛ إعدادات الإنتاج ترفض التشغيل إن لم تُضبط بيانات المدير والمفتاح.

### قائمة تحقق قبل الإطلاق

1. أنشئ أسرار الإنتاج داخل مدير الأسرار في منصة الاستضافة، ولا تنسخ ملف `.env` المحلي أو ترفعه.
2. استخدم قاعدة بيانات ومجلد صور جديدين على تخزين دائم. مجلد `data/` وقواعد SQLite وملفات WAL مستثناة من Git؛ لا تنشر قاعدة التطوير المحلية.
3. أضف بيانات التواصل الفعلية وراجع نصوص الموقع في إعدادات الإدارة، ثم أضف مشاريع وصوراً حقيقية. عينات المشاريع تُزرع محلياً فقط ولا تُضاف إلى قاعدة بيانات إنتاج جديدة.
4. فعّل HTTPS على proxy/الاستضافة، وتأكد أن الـ proxy يمرر `X-Forwarded-Proto` و`X-Forwarded-For` بشكل موثوق.
5. أنشئ نسخة احتياطية مشفرة لقاعدة SQLite والملفات المرفوعة، واختبر الاستعادة قبل الإطلاق.
6. شغّل `npm run build` و`npm run lint` ثم اختبر `/health` وتسجيل الدخول وصفحات الموقع بعد النشر.

**مهم:** بيانات الاعتماد ومفتاح التوقيع الظاهرة في ملف البيئة المحدد أثناء المحادثة يجب اعتبارها مكشوفة. استبدل كلمة مرور المدير ومفتاح `JWT_SECRET` فوراً قبل النشر، وأبطل أي جلسات قديمة بتغيير المفتاح. لم أقرأ ملف `.env` أو أعدّله.

## أوامر المشروع

| الأمر | الوظيفة |
| --- | --- |
| `npm run dev` | تشغيل الخادم وواجهة التطوير على المنفذ 3000 افتراضياً. |
| `npm run build` | إنشاء نسخة الواجهة الإنتاجية داخل `dist`. |
| `npm start` | تشغيل خادم Node.js؛ شغّل `npm run build` قبله للإنتاج. |
| `npm run lint` | تشغيل فحص TypeScript للمشروع. |

ملاحظة: `npm run lint` يشغّل فحص TypeScript لكل المشروع، وقد يعرض أخطاء أنواع موجودة حالياً في `server/db.ts` و`server/storage.ts`. هذه الأخطاء منفصلة عن تثبيت الحزم وتشغيل الموقع.

## توضيح خطأ `npm ERESOLVE`

كان الخطأ بسبب تعارض إصدارات داخل المشروع:

- المشروع كان يطلب `esbuild@^0.25.0`.
- إصدار Vite 8 المستخدم (`vite@8.3.8`) يطلب اختيارياً إصدار `esbuild@^0.27.0` أو `^0.28.0`.
- لذلك لم يتمكن npm من اختيار مجموعة إصدارات تحقق الشرطين، وأوقف التثبيت برسالة `ERESOLVE`.

تم تحديث `esbuild` في `package.json` إلى `^0.28.0` ومزامنة `bun.lock` مع هذا التغيير. في نسخة المشروع المحدّثة استخدم:

```powershell
npm install
```

إذا فشل التثبيت بسبب بقايا تثبيت قديم، احذف مجلد الحزم وأعد المحاولة من مجلد المشروع:

```powershell
if (Test-Path node_modules) { Remove-Item -Recurse -Force node_modules }
npm install
```

لا تستخدم `--force`؛ فهو يتجاوز فحوص التوافق. كما لا يفترض أن تحتاج إلى `--legacy-peer-deps` بعد تحديث ملفات المشروع.
